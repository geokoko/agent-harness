# Design direction and preferences

Use the user's brief and existing approved design system first. These preferences
preserve the useful direction-setting intent of the former design-consult and
design-review skills; they are not a compliance checklist or an automatic ban list.

- Give the interface a recognizable identity through purposeful type, composition,
  content and imagery. Choose typography deliberately; an existing system font
  can be the right choice. Explain a new font/dependency before introducing it.
- Let hierarchy and content determine the layout. Marketing pages need a clear
  promise, credible proof and an appropriate next action. Task-heavy applications
  need readable information, clear state and efficient actions. Hybrid interfaces
  can vary by section.
- Avoid filling space with interchangeable feature cards, decorative blobs or
  repeated slogans. Cards, gradients, centered layouts and rounded corners are
  valid when they serve the content and interaction. Point to the actual problem
  when proposing a change; a recognizable visual pattern is not itself a defect.
- Use concrete language and authentic assets. Preserve the user's brand and
  factual claims; make illustrative or placeholder content unmistakable.
- Keep spacing, color roles, control states and motion coherent. Functional
  motion should clarify an interaction and respect reduced-motion preferences.

When a brief or reusable design record is useful, capture the audience/context,
main screen job, intended impression, layout rationale, typography and spacing
scale, color tokens, component/state examples, responsive stance and asset needs.
Use the project's format and omit sections that do not help the current task.

Separate a taste recommendation from a reproducible usability/accessibility
failure. Apply relevant standards to the actual element and context; arbitrary
color/font counts, weighted letter grades and personal dislikes are not proof.
