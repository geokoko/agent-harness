# Rendered UI evidence

Inspect the rendered affected pages and states before making visual claims.
Use representative desktop/mobile widths and include loading, empty, error,
focus and interaction states when relevant. Screenshots cannot establish
keyboard behavior, accessible names, or complete accessibility compliance.

Ground findings in observed hierarchy, readability, contrast, focus, labels,
responsive behavior and the project's design system. Do not turn personal
font choices, card layouts or color stereotypes into universal defects.
Check orientation where relevant: can the user identify the product/page, their
current location, available actions and how to navigate? Search is useful only
when the interface needs it, not a requirement for every page.
Link the inspected screenshot or other evidence and disclose untested states.

A review remains report-only unless fixes are authorized. For an authorized
fix, re-render the affected state and compare before/after; do not auto-commit
or revert unrelated work. Tool availability is not permission to install one.
